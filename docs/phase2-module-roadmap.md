# 阶段二：按模块细切片推进路线图

> 脚手架（去品牌、配置隔离、冒烟）已完成。本文件是二次开发的**推进顺序与过关标准**。  
> 工作流：`design.md` → `tasks.md` → 只改 `new_shop/` → 过关验证。规范见 `.steerin/feature-designer.md` / `feature-task-maker.md`。  
> 缺口 ID 对照：[todo-gaps.md](./todo-gaps.md)、[payment-reliability.md](./payment-reliability.md)。

---

## 1. 工作节奏

```text
选切片 → design.md → tasks.md → 编码（new_shop）→ 过关验证 → 下一切片
```

| 约定 | 说明 |
|------|------|
| 切片粒度 | 0.5～2 天可关闭；禁止一次做完整个支付/履约域 |
| 文档落点 | `docs/features/[模块]/[版本]/{server\|web\|uniapp}/` |
| 表变更 | 加字段/新表优先；主表名与主外键尽量不动 |
| 表通用化 | 夹在对应业务切片，不单开整库重构 |
| 禁止 | 跳过 `tasks.md` 直接大改；未过关就开下一 P0/P1 切片 |

---

## 2. 模块总序

```text
M0 行业开关底座
 → M1 支付可靠性 P0
 → M2 履约/退款 P1
 → M3 登录安全 P1
 → M4 物流字段通用化 P2（可与 M2 后并行）
 → M5 按客户加项（非默认必做）
```

## 3. 细切片清单与过关标准

### M0 行业开关底座

| 切片 ID | 内容 | todo-gaps | 文档目录 | 过关标准 |
|---------|------|-----------|----------|----------|
| **M0-1** | 配置键约定 + server 读取封装 | GEN-03 前置 | [features/industry-config](./features/industry-config/) | 键有种子/SQL；业务可读布尔/枚举默认值；缺键不崩 |
| **M0-2** | 用户审核可关（GEN-03） | GEN-03 | 同上后续版本 | 关：注册/登录默认通过、可下单；开：与现网卡审核一致 |
| **M0-3** | 管理端开关编辑（极简） | — | web 端 design | 后台能改 M0 键并即时生效（或可接受重启/下次请求读库） |

**当前进度**：M0-1 **已实现**；迁移 SQL 用户侧已执行。下一刀建议 **M0-2**（GEN-03）或按需先做 **M1-1**（PAY-02）。

### M1 支付可靠性 P0

| 切片 ID | 内容 | todo-gaps | 过关标准 |
|---------|------|-----------|----------|
| **M1-1** | 回调金额与订单金额校验 | PAY-02 | 金额不符拒写已支付；有日志 |

### M2 履约 / 退款 P1

| 切片 ID | 内容 | todo-gaps | 过关标准 |
|---------|------|-----------|----------|
| **M2-1** | 人工「标记退款完成」专用接口 | FUL-06 | 专用 API，状态语义清晰，非通用 update 滥改 |
| **M2-2** | 发货/取消乐观锁 | FUL-05 | 并发下不会「已发货仍取消成功」类脏写 |
| **M2-3** | 小程序确认收货路径对齐 | FUL-02 | 前端打到真实后端路由且状态正确 |
| **M2-4** | 微信自动退款闭环 | PAY-05 / FUL-01 | 可报价加项；同意后退款到账+状态+库存规则按 design |

### M3 登录安全 P1

| 切片 ID | 内容 | todo-gaps | 过关标准 |
|---------|------|-----------|----------|
| **M3-1** | `session_key` 仅服务端 | AUTH-01 | 响应不再回传 session_key；解密仍可用 |
| **M3-2** | phone 索引 + 唯一（方案 A） | AUTH-02 | 登录查询走索引；并发不轻易双用户 |
