# 二次开发产品定位：行业 · 客户 · 获客 · 目标

> 基于对 `old_shop`（启运冻品 / fresh-shop）的分析，以及单商户通用商城二次开发方向整理。  
> 技术参考只读：`old_shop/`；实现落在 `new_shop/`。

---

## 1. 一句话定位

把开源单商户商城框架沉淀为 **可重复部署的通用微信小程序商城**，为「有货可卖、想独立开小程序店」的中小商家提供：**系统交付 + 配置部署上线 + 可选技术维护**。

不是做多商户入驻平台，也不是代运营卖货。

---

## 2. 行业认知

### 2.1 所处赛道

属于 **中小商家私域电商 / 数字化零售交付**，不是纯互联网流量平台（美团、拼多多这类）。

常见需求：

- 品牌或门店要有 **自己的微信小程序商城**（私域、会员、复购）
- 后台能管商品、订单、发货、员工权限
- 用商家自己的微信支付收款
- 希望 **独立数据和独立品牌**，而不是挂在别人的大平台里当一个小店招

### 2.2 原项目行业背景

`old_shop` 面向 **冻品 / 生鲜类** 经营场景，除标准电商能力外，还带有偏「小 B」的能力痕迹，例如：

- 客户信息审核
- 现结 / 月结
- 配送员等

说明这套底座既能做 **ToC 零售**，也能覆盖 **门店进货 / 小批发** 一类场景；通用化后应把行业特色做成 **开关**，默认走标准 B2C。

### 2.3 这套软件在行业里的作用

它是 **「单商户线上卖货操作系统」**，不是流量撮合平台。

```text
消费者 ──微信小程序──► 商城系统（商品/购物车/订单/支付）
                              │
商家运营 ◄──管理后台──────────┘（商品、订单、用户、权限、配置）
```

对商家的价值：

| 能力 | 作用 |
|------|------|
| 小程序前台 | 独立品牌门店、浏览下单支付 |
| 管理后台 | 运营商品与订单、管员工权限 |
| 独立部署 | 数据在自己这边，AppID/商户号自己的 |
| （可选扩展） | 积分、余额、审核、月结等按行业打开 |

## 3. 技术形态结论（影响怎么卖）

| 项 | 结论 |
|----|------|
| 租户模型 | **单商户**，非多租户 SaaS |
| 部署方式 | **一家客户一套部署、独立库** |
| 微信 / 支付 | **客户自己的** AppID、Secret、商户号 |
| 首期产品形态 | 单商户 **B2C / 小 B** 通用版（行业能力用配置开关） |

代码与库中无 `tenant` / 多商户隔离设计；做多租户入驻平台不在首期范围。

## 4. 目标客户

### 4.1 核心客户画像

**有货可卖 + 有（或愿意办）微信小程序主体 + 需要独立商城系统 + 愿意为交付/部署付费的中小经营者**，或其服务商。

### 4.2 优先客户（高匹配）

1. **中小零售 / 特产 / 零食 / 日用 / 配件等商家**  
   要小程序商城 + 后台，标准下单支付即可。  
2. **生鲜、冻品、食材半批发或门店供货**  
   与原项目接近；可启用审核、月结等开关做差异化。  
3. **本地单品牌门店或小型连锁（先单店部署）**  
   要会员下单与自有品牌，不做平台入驻。  
4. **建站 / 代运营 / 本地数字化服务商**  
   他们接商务，你提供可部署内核（白标），是渠道型客户。

### 4.3 谨慎或暂不主攻

| 类型 | 原因 |
|------|------|
| 要「多商户入驻平台」 | 当前架构不支持，改造量大 |
| 只要官方微信小店、不要独立系统 | 需求错配 |
| 无营业执照 / 过不了小程序与支付资质 | 上线风险高 |
| 超大集团、深度 ERP 一体化 | 超出通用商城首期范围 |
| 只要 H5/App、明确不要微信 | 现成重心在小程序 |

## 5. 你提供什么服务（商业模式）

可以做成 **技术向一条龙**，但建议拆开报价，避免无限改需求。

### 5.1 服务内容

| 阶段 | 内容 | 建议卖法 |
|------|------|----------|
| 产品底座 | 自有 `new_shop` 通用商城（去行业耦合、可配置） | 你的资产，不单卖「裸开源」 |
| 项目交付 | 换品牌/类目/主题，少量定制页面或流程 | **项目款**（一次性） |
| 上线实施 | 配 AppID/支付/域名、部署、初始化数据、后台培训 | 含在项目款或 **实施费** |
| 技术维护 | Bug 修复、小需求、协助证书/服务器/发版、微信审核协助 | **年维保** 或按次 |

### 5.2 建议产品分档

1. **标准部署**：通用版 + 配置换皮 + 上线（几乎不定制）  
2. **定制项目**：标准 + 流程/字段/页面定制  
3. **年度维护**：保障可运行与小改动  

### 5.3 责任边界（写进合同）

- **客户负责**：营业执照、小程序主体、微信支付商户号、域名与备案（你可指导或代办另计费）  
- **你负责**：系统部署、配置联调、约定范围内的定制与维保  
- **一般不包含**（除非另签）：代运营、投放获客、客服话术、货源供应链  

### 5.4 代码与知识产权（需自行定策略）

常见做法（择一写清）：

- 只部署运行权，不交付完整源码；或  
- 交付源码但加价 / 约定不得转售；或  
- 内核闭源，客户侧仅配置与主题  

开源协议层面：上游按 **MIT** 使用时注意保留声明；你在通用版上的新增代码可另有商业授权策略。

## 6. 如何获客

个人/小团队起步，适合 **低成本、可演示、口碑型** 获客，而不是先砸大广告。

### 6.1 先准备「能看的东西」

- 自己部署一套 **演示环境**（通用版小程序 + 管理后台）  
- 一页介绍：能做什么、多少天能上线、含不含支付与培训  
- 案例：哪怕是自己的演示站 + 1～2 个真实小单  

### 6.2 可行渠道

| 渠道 | 做法 |
|------|------|
| 本地与人脉 | 老乡、朋友介绍的实体店、供应链；先做 1 个标杆 |
| 服务商合作 | 找做设计/代运营/本地推的公司，你做技术交付，分成或分包 |
| 内容获客 | 短视频/公众号讲「中小商家自己的小程序商城」；附演示与咨询 |
| 平台接单 | 猪八戒、电鸭、即刻/社群、程序员接单群等发「小程序商城独立部署」 |
| 垂直行业 | 冻品/食材群、本地餐饮供应链群（你对原项目最熟） |

### 6.3 获客话术（示例）

> 给您一套 **独立的微信小程序商城**（商品、购物车、订单、支付、后台），数据在您自己服务器，用您自己的小程序和商户号。我们负责部署上线和基础培训，也可按年提供技术维护。

### 6.4 早期成交策略

- 第一单：需求简单、允许用标准版、周期短，用来打磨交付清单  
- 报价拆开：软件实施 / 定制人天 / 年维保  
- 合同写清：几轮修改、超范围怎么算、客户资质延误谁负责

## 7. 目标（分阶段）

### 7.1 总目标

基于 `old_shop` 学习并二次开发出 **`new_shop` 通用单商户商城**，以此为产品接中小商家（及服务商）的交付与维护业务。

### 7.2 阶段目标

| 阶段 | 目标 | 完成标志 |
|------|------|----------|
| **阶段一：学习** | 掌握表结构、架构、接口与核心流程 | 模块文档读完；三端本地可跑 |
| **阶段二：产品化** | `new_shop` 去冻品品牌与强行业耦合，配置化开关 | 可一键/文档化部署演示站 |
| **阶段三：交付能力** | 标准部署清单、报价模板、上线检查表 | 能独立完成「配置→上线→培训」 |
| **阶段四：接单验证** | 完成 1～2 个真实或准真实客户 | 有回款与可写案例 |
| **阶段五：稳定接单** | 标准版为主、定制可控；维保形成复购 | 渠道或口碑持续有询盘 |

### 7.3 个人能力目标（结合现状）

- 已有：约 5 年 Go，能扛后端、部署、订单支付类问题  
- 补齐：管理端 / 小程序以 **能改、能联调、能出包** 为标准，不追求纯前端深度  
- 业务：能向客户讲清单商户独立部署、资质边界与服务分档  

### 7.4 非目标（首期明确不做）

- 多租户商户入驻平台  
- 大型中台 / 全渠道 ERP  
- 纯流量运营公司

## 8. 与技术路线的对应关系

```text
old_shop（只读学习）
    → 理解单商户商城全链路
new_shop（通用商城内核）
    → 去品牌、配置化、可重复部署
客户项目（独立部署）
    → 独立库 + 客户 AppID/支付 + 换皮/小定制 + 维保
```

学习文档见同目录模块系列；环境启动见 `run-backend-now.md`、`run-uniapp-win10.md`。

## 9. 自检问题

1. 我卖的是平台入驻还是独立商城？→ **独立商城**  
2. 客户数据是否隔离？→ **独立部署、独立库**  
3. 微信与支付用谁的？→ **客户自己的**  
4. 我是否做代运营？→ **默认不做，除非另签**  
5. 首期最理想客户是谁？→ **有货、有主体、要独立小程序店的中小商家或其服务商**
